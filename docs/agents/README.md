# docs/agents 的维护规则

> scope: 本目录 ｜ 触发: 新增/改写任何一个 topic 文件 ｜ 复核: 2026-11-24

本目录是**按需读取**的规范正文，根索引（`AGENTS.md`）只负责指路。

## 一个文件 = 一个可独立改动的领域

- 跨端主题：`core.md`（脚本写法）、`versioning.md`（版本/标签/模块详情）、`api-matrix.md`（API 对照）、`rules-and-regex.md`（pattern/可覆盖段/MITM）、`testing.md`、`distribution.md`、`env-lib.md`
- 客户端：`clients/<端>.md`，一文件一端，互不引用（换端时只读一个文件就够）
- `sources.md`：所有出处的汇总表

## 每份文件的头三行

```
# 标题

> scope: … ｜ 触发: 改什么的时候该读 ｜ 上游: 官方文档或 sources.md ｜ 复核: YYYY-MM-DD
```

`触发` 写具体动作（"改该端的模块/插件/脚本"），不写"相关文档"这种废话——agent 靠这一行判断要不要读。

## 写新内容的规矩

- 新细节写进对应的 topic 文件，**不许写回根索引**。根索引只有：定位、硬约束、分流表。
- 一条规则一个出处。官方文档能查到的写 ✅ + URL；只在社区代码里见到的写 🟡；没核实的写 ⚠️ 并说明缺什么。
- 不在本目录复述官方文档全文。上游改了就以上游为准，这里只留"差异点 + 坑"。
- 改完更新该文件的 `复核` 日期，并在 `sources.md` 补一行。

## 体量

| 层级 | 目标 | 依据 |
|---|---|---|
| 根索引 | ≤ 150 行 | Claude Code 建议单个 memory 文件 < 200 行；实测索引型 AGENTS.md 多在 200 行内 |
| 单个 topic 文件 | 一次任务能读完（≈ 100–250 行） | 同上 |
| 根索引全链 | < 32 KiB | Codex 的 `project_doc_max_bytes` 默认 32 KiB，超出即截断 |

有内容撑爆单文件时，按"端"或"主题"再切一层，不要靠删内容解决。
